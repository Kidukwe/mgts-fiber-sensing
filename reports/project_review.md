# Проверка проекта МГТС

Дата: 16 октября 2026. Проверена локальная версия building-temperature-v2:
постановка, Python-код, обучение, события, CLI, данные, отчёты и поставка.
Проверка не означает приёмку командой или прохождение удалённого CI.

## Вывод

Ожидаемый результат кейса реализован: Python-пайплайн цифровой обработки
предоставленных профилей и обученные регрессионные модели. Есть воспроизводимое
обучение, сохранение моделей, сравнение baseline и повторное применение без fit.
Для демонстрации решения комплект пригоден после исправлений этой проверки.
Эксплуатационное качество обнаружения аварий пока не доказано.

## Найдено и исправлено

### Расширение очага влево теряло начало события

Раньше сопоставление соседних во времени компонент проверяло grid только первой
зоны новой компоненты. Если событие начиналось в зоне 1, а затем распространялось
в зоны 0–1, зона 0 отсутствовала в предыдущей компоненте. Открывалось новое событие;
первое подозрение терялось, start и detected_at сдвигались. Короткий эпизод мог
вообще не набрать два подтверждения.

Исправлено сопоставление по любой общей зоне с совместимой сеткой, с сохранением
проверок потока, блока, пересечения и последовательности времени.
Регрессионный тест `test_expanding_event_keeps_start_and_confirmation` до исправления
показывал начало 00:49 вместо 00:48; после исправления сохраняется 00:48,
подтверждение — 00:49.

Код: `src/mgts_sensing/solution.py`, `build_alerts`.

### Начало replay не использовало доступный температурный фон

Регрессионному прогнозу уже доступны пять предыдущих профилей, а детектор
начинал собственную историю с нуля. Когда прогноз успевал следовать изменившейся
температуре, устойчивый сдвиг первых пригодных наблюдений мог остаться незамеченным.

Теперь `make_samples` передаёт первые пять прошлых наблюдений каждой непрерывной
истории как `baseline_seed`. Детектор инициализируется ими без использования
текущего target. Seed обновляется только при начале новой пригодной истории.
Тест `test_replay_uses_available_past_for_first_background` до исправления не находил
нагрев; после исправления обнаруживается сдвиг с первого пригодного наблюдения.

Код: `src/mgts_sensing/solution.py`, `make_samples` и `build_alerts`.

### Сборка допускала устаревшие результаты

Скрипт упаковки проверял лишь `status=complete`. После изменения кода можно было
создать архив с новыми исходниками и прежними артефактами, не соответствующими коду.

Добавлен общий валидатор `src/mgts_sensing/artifacts.py`: проверка SHA модулей,
соответствия модели исходнику, восстановления test-прогнозов, MAE/RMSE, числа
профилей/наблюдений, причинности timestamps и учёта событий. Сборка вызывает
валидатор до создания ZIP. Ошибки сигнализируются исключениями, а не отключаемыми
через python -O assertions. Для проверки поставки без raw добавлен `--skip-raw`.
Тест изменяет веса и fingerprint кода и подтверждает отказ проверки.

### Версия пакета расходилась с метаданными

`pyproject.toml` содержал 0.3.0, а `mgts_sensing.__version__` — 0.1.0.
Согласована версия 0.3.0, smoke-тест теперь сравнивает её с установленной
метаинформацией пакета вместо проверки устаревшей константы.

## Что проверено

- 223 теста проходят, включая три новых сценария этой проверки; Ruff и diff-check чистые.
- Все шесть CSV обработаны повторно: 6749 профилей; исходные SHA256 сохранены.
- Модель и scaler обучаются по train; Δ-пороги признаков оцениваются по train,
  alpha и вариант признаков выбираются по validation.
- Признаки собственного прогноза строятся из пяти предыдущих профилей,
  current target в них не входит. Предыдущие доступные наблюдения за границей
  split разрешены действующим последовательным протоколом.
- Маркеры конца трассы исключены; разрывы, отсутствующие участки и изменения
  сетки разрывают историю. Часовой пояс без offset назначается UTC+3 явно.
- Сохранённые прогнозы всех шести моделей восстановлены из JSON и проверены
  по NPZ; проверены timestamps, метрики и согласованность каталогов событий.
- Реальный batch replay `2.csv`: 23350 прогнозных строк; 32 кандидата на всей
  записи. Это проверка запуска, не новая оценка качества и не каталог только test.
- Функциональная синтетика: 4 введённых / 4 совпавших события, подтверждение
  через один профиль. Синтетика остаётся разработочной.
- Проверены все локальные ссылки/изображения HTML. ZIP распакован отдельно,
  и встроенный verify_solution.py успешно выполнен с кодом из самого архива, без raw CSV.
- Каталог на отчётном test-времени пересчитан: 119 кандидатов вместо 141.
  Число изменилось из-за начального фона и объединения; это не доказательство
  увеличения precision. MAE регрессии не изменились: 0.0702–0.1861 °C.

## Ограничения, которые нельзя закрыть только кодом

1. Нет независимых меток протечек/аварий. MAE прогноза не измеряет recall или
   цену ложных тревог. Для пилота нужен журнал происшествий/проверок инженера.
2. Записи уже использовались при разработке v1/v2. Повторные результаты —
   исследовательская оценка, а не новый независимый test. Нужен другой период/объект.
3. Разрешение 0.25 см не подтверждает шаг хранения каждого CSV: raw x имеет
   разные численные шаги. Индексные метры — явно отмеченное допущение; для
   реальной локализации нужна схема трассы и подтверждение преобразования.
4. Timestamp не доказывает момент доступности полного профиля. Реализован
   batch replay с причинными признаками, не измерен SLA онлайн-обнаружения.
5. Тип объекта, режимы HVAC и паспортные абсолютные пределы неизвестны.
   Постоянный перегрев с начала записи без изменений требует внешних пределов.
6. Пространственное объединение остаётся жадным трекером компонент. Расхождение
   одного очага на несколько и слияние нескольких причин требуют отдельной оценки.
