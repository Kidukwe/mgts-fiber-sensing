# МГТС — мониторинг температуры инженерных коммуникаций

Готовый локальный Python-пайплайн: проверка CSV → пространственная цифровая
обработка → обученная регрессия следующей температуры → кандидаты аномалий →
HTML-отчёт с картами температуры, метриками и каталогом событий.

Сценарий: поиск перегревов, охлаждений и локальных изменений, которые могут
сопровождать протечки в здании. Причина события требует проверки инженером.

Актуальная постановка после ответа руководителя и снятия ограничения 40 точек:
[docs/task_revision.md](docs/task_revision.md). Сравнение со всеми шестью PR:
[docs/pr_comparison.md](docs/pr_comparison.md).

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev,solution]'
# Поместите 1.csv … 6.csv из MGTS_data.zip в MGTS_data/.
python scripts/run_solution.py --data-dir MGTS_data --output-dir artifacts/final
# Откройте artifacts/final/report.html в браузере.
```

Отчёт работает локально, не требует сервера или интернета. Python >=3.10.
Время прогона зависит от компьютера; исходный набор около 759 МиБ.
Повторный запуск в тот же каталог пересоздаёт производные результаты.

```bash
pytest
ruff check .
python scripts/benchmark_solution.py --output-dir artifacts/benchmark-new
python scripts/audit_data.py --data-dir MGTS_data --report-dir reports/ingestion
python scripts/verify_solution.py
# Применить обученную модель к другому CSV того же сенсора/канала без переобучения:
python scripts/predict_solution.py --input /path/to/new.csv \
  --model artifacts/final/2/model.json --output-dir artifacts/replay-new
python scripts/package_solution.py
```

Последняя команда создаёт `artifacts/submission.zip`: код, документацию,
обученные модели, результаты и демонстрацию. Исходные CSV в архив не включаются.

## Подтверждённые параметры

- Сигнал: °C, точность ±0,1 °C.
- Пространственный шаг: 0,25 см = 0,0025 м, по ответу руководителя.
- −300: конец волоконной трассы, исключается из аналитики.
- Timestamp без часового пояса: фиксированный UTC+3. Явные offset сохраняются.
- Время получения полного профиля неизвестно: измерительное время не равно
  подтверждённому времени доступности для онлайн-системы.

Числовая ось x в CSV имеет разные шаги. Она сохраняется отдельно как raw_x.
Расстояния в отчёте рассчитываются **по индексам** с заявленным шагом; это
допущение нужно проверить по схеме трассы перед физической локализацией.
Протяжённость кандидата — размер покрывающих его зон волокна, а не точный очаг.

## Модель и оценка

На каждом файле отдельно: 60% ранних профилей — обучение, 20% — validation,
20% — test. Обучаемая модель — многовыходная ridge-регрессия приращения медианы
и локальных горячих/холодных экскурсий. 24 признака описывают предыдущие
изменения, пространственную форму, энергию высоких пространственных частот
и местное время. Сравниваются temporal-only и spatial/DSP варианты одной модели;
доли изменившихся точек и длины их серий используют пороги только по train. Масштабирование рассчитывается только по train.

На validation выбирается ridge с alpha 0.1/10/1000, persistence, rolling median или постоянная медиана зоны из train.
Основная метрика — MAE прогноза медианной температуры, дополнительная — RMSE.
Каждый профиль получает одинаковый вес независимо от числа зон.
Горизонт — следующий пригодный профиль, фактические origin/target timestamps
сохраняются. Большие разрывы и изменения сетки не соединяются.

Детектор объединяет ошибки прогноза и отклонение от устойчивого прошлого уровня.
Фон замораживается при подозрении. Ошибку прогноза должно подтверждать направление
реального отклонения от фона. Подтверждение — два последовательных профиля.
Приоритет учитывает вместе амплитуду, длительность и протяжённость.
Статистические пороги — настройки алгоритма, а не установленные границы аварии.

Результаты реального прогона: [reports/final_results.md](reports/final_results.md).
Метрики обнаружения реальных аварий без внешней разметки не вычисляются.
Контролируемая синтетика проверяет поведение, а не доказывает эксплуатационное качество.

Первые отчётные test-блоки уже просмотрены при разработке v1. Результаты v2
на этих же записях — повторная исследовательская оценка; новая независимая
проверка требует другого периода или объекта.

## Выходные файлы

- `report.html`, `results.md`, `solution.json`: демонстрация и общая сводка.
- Для каждого CSV: `model.json`, `metrics.json`, `events.json`, `issues.jsonl`, `diagnostics.png`.
- `predictions.npz`: test-прогнозы всех трёх величин, actual, baseline, признаки,
  timestamps, forecast_origin и индексы исходных строк/участков. Загружается
  через `numpy.load(..., allow_pickle=False)`.
- `model.json` содержит scaler, коэффициенты, intercept, выбранную модель,
  параметры, единицы, границы выборок и SHA256 исходника.
- Общая сводка содержит SHA256 кода, версии среды и проверку неизменности raw.
