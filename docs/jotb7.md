## Предложение контракта, не утверждённый контракт команды

Архитектор зафиксировал точный API в `docs/jotb7_contract.md` до реализации.
Исследовательские настройки первого запуска:

- `index_start=0`, `index_stop=2120` (exclusive), `zone_width=40`;
- `history_size=5`, включая текущий профиль;
- `max_gap_seconds=121` — диагностическая граница для первого `2.csv`,
  не физический порог события;
- `min_valid_fraction=1.0` — строгая исследовательская политика полноты;
- все параметры доступны явно через CLI и сохранены в config.

Вход: `ProfileResult` существующего `iter_profiles`. Сырые Profile не менять.
Проверять строго возрастающие конечные координаты и наличие выбранного
участка. Совместимость выбранных x сравнивать точно с доступной прошлой
сеткой, не вычислять «общую сетку» по будущему датасету. Изменение полного
хвоста вне выбранного участка допустимо только при равенстве выбранных x.

Сначала пространственная агрегация каждого профиля, затем признаки истории
зон. По зоне: median, minimum, maximum, maximum-minus-median,
median-minus-minimum и std с ddof=0. Значения с sentinel_mask=True или y==-300
исключаются только в производных вычислениях. Сохранять число доступных
точек, полноту и долю подозрительных значений. Без доступных значений либо
при недостаточной полноте числовые признаки отсутствуют, не равны нулю.
Неполная крайняя зона должна иметь явный флаг и описанную политику знаменателя.

По H зональным медианам: lag_medians (current-first), delta,
rate=delta/реальный Δt, rolling_mean, rolling_std (ddof=0), число доступных
значений. Среднее равновесовое по профилям, не среднее за фиксированную
длительность. Не задавать долю повышенных точек через выдуманный порог.

История не соединяет файлы, устройства/каналы, naive/aware домены,
несовместимые выбранные сетки, отклонённые записи или большие разрывы.
Дубликаты/обратное время должны отражаться в отчёте и разрывать историю;
не удалять их незаметно. Часовой пояс не назначать автоматически.

Выход: JSONL со строкой на текущую зону, координатами/индексами, временем,
source/row/line, block_id, history_start/count/ready, происхождением истории,
именованными числовыми признаками и списком quality_flags. Во время прогрева
сохранять пространственные признаки и flag, но не выдавать частичную историю
за полное H-окно. Массивы — JSON arrays; пропуски — null; NaN/Inf в JSON запрещены.

## Передача и воспроизводимость

CLI: `python scripts/build_features.py --input MGTS_data/2.csv
--output-dir artifacts/jotb7`. Сохранять `features.jsonl`, `schema.json`,
`config.json`, `report.json`, `issues.jsonl`. Политика и schema version помечены
`proposal`, единицы null. Проверять SHA256 входов до/после. Отчёт включает все
записи ingestion, причины исключений, число агрегированных зон, полных окон,
строк прогрева и temporal blocks. Отдельная маленькая синтетическая fixture
имеет ту же схему и не смешивается с реальными данными.

## Приёмка

- Точные численные тесты median/min/max/std/экскурсий и temporal формул.
- Узкий пик/провал виден в min/max, даже если не влияет на median.
- Частичная/полная маска, порог полноты, хвостовая зона, несовместимые x.
- Реальное Δt, равенство gap границе, переход файла/потока/сетки.
- Повреждённая строка разрывает историю; будущие значения не меняют прошлое.
- Повторный запуск воспроизводим, входные массивы/CSV/notebook сохранены.
- Существующие и новые тесты, Ruff, diff-check и реальный запуск `2.csv`.
- Независимый критик проверяет контракт, diff и экспорт перед handoff.
