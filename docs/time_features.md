# Причинные временные признаки JOTB-3

`iter_windows` в `mgts_sensing.windowing` формирует историю из H профилей,
включая текущий. На прогреве результатов нет. `compute_time_features` в
`mgts_sensing.time_features` возвращает признаки по каждой координате.
Target и обучение в эту часть не входят.

## Минимальный пример с ingestion

Вход должен быть упорядочен по времени внутри непрерывных блоков одного
файла/устройства/канала. Функция не сортирует и не интерполирует данные.
В примере 240 секунд — лишь явный демонстрационный порог; рабочее значение
нужно обосновать частотой конкретного потока, не подбирая по test.

```python
from itertools import groupby
from pathlib import Path

from mgts_sensing.io import iter_profiles
from mgts_sensing.time_features import compute_time_features
from mgts_sensing.windowing import iter_windows

results = iter_profiles([Path("MGTS_data/3.csv")])
for loaded, run in groupby(results, key=lambda result: result.loaded):
    if not loaded:
        for result in run:
            print(result.row_number, result.issues)
        continue
    profiles = (result.profile for result in run)
    for window in iter_windows(profiles, history_size=3, max_gap_seconds=240):
        features = compute_time_features(window)
        print(window.profiles[-1].timestamp, features.delta_seconds,
              features.valid_count.min())
```

Разделение на `run` обязательно: нельзя просто отфильтровать отклонённые
записи и соединить историю до/после них. Новый вызов `iter_windows` начинает
локальную нумерацию сессий заново. `session_index` не является глобальным ID:
для нескольких вызовов вызывающий код сохраняет собственный идентификатор
серии. Смена файла, устройства/канала, известности timezone, координатной сетки
или превышение порога временного интервала сбрасывает прогрев. При неизменном
ключе блока дубликаты времени и обратный порядок вызывают `ValueError`.

## Смысл признаков

При N координатах `lag_values` имеет форму `(H, N)`: строка 0 — текущий
профиль, строка 1 — предыдущий. `-300` и точки с `sentinel_mask=True` исключены
только в копиях признаков: на их месте NaN. Исходные профили не изменяются.
Это не метка неисправности и не утверждение о физическом смысле маркера.

- `delta` — текущее минус предыдущее измерение по каждой координате.
- `rate` — `delta` / реальный интервал секунд между последними профилями.
  Единицы — единицы y в секунду; физические единицы пока не подтверждены.
- `rolling_mean` / `rolling_std` — среднее и стандартное отклонение доступных
  значений окна, включая текущее; `ddof=0`.
- `valid_count` — число использованных значений в каждой координате.

Окно задано количеством профилей, а не длительностью. При нерегулярных
интервалах H=3 может покрывать разное число секунд. Среднее и стандартное
отклонение равновесовые по доступным измерениям, а не взвешенные по времени.
Поэтому их нельзя называть средним сигналом за фиксированные пять минут.
Для задач с фиксированным временным горизонтом нужны отдельные правила окон
и сопоставления target; текущая реализация таких правил не предполагает.

Для времён 0, 10, 30 секунд и значений 1, 3, 9 в одной координате:
`lag_values=[[9], [3], [1]]`, `delta=6`, `rate=0.3`,
`rolling_mean=13/3`, `rolling_std=sqrt(104/9)`, `valid_count=3`.
Для истории `[1, -300, 9]` доступны два значения: среднее 5, стандартное
отклонение 4, но `delta` и `rate` равны NaN, поскольку предыдущее измерение
замаскировано. При полностью замаскированной истории count=0, mean/std=NaN;
при единственном доступном измерении std=0.

Все выходные массивы read-only; `x` скопирован. `window` сохраняет происхождение
использованной истории. Признаки используют только доступное прошлое и текущий
момент, поэтому не подходят для предсказания этого же текущего измерения:
будущий target необходимо определить отдельно. NaN, зависимость соседних
координат, split и метрика требуют решений ML-постановки перед `fit`.
