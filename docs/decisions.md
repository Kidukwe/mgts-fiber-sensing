# Решения проекта

## Действующая постановка от 16 октября 2026

Последний запрос пользователя завершить решение и ответ руководителя заменяют
прежнее ожидание утверждения target. Выбранная командой реализация: регрессия
следующей температуры плюс детекция и ранжирование аномалий без меток аварий.
Это инженерный выбор для хакатона, а не требование руководителя использовать ridge.

Подтверждено руководителем через сообщение пользователя:

- °C; точность ±0,1 °C; пространственное разрешение 0,25 см.
- −300 — конец трассы, его можно не рассматривать.
- Naive timestamps — UTC+3, фиксированный offset.
- Рабочий сценарий — здание и инженерные коммуникации: протечки, перегревы,
  аномальные понижения температуры.
- Значимость определяется совокупностью параметров; заданных физических
  порогов амплитуды/размера/длительности нет, выбор алгоритма свободный.

Принято в реализации:

- Raw неизменяемы и исключены из Git, SHA256 до/после обработки.
- Обучение/validation/test = 60/20/20 по времени каждого файла.
- Target — медиана и горячая/холодная экскурсии следующего профиля зоны.
- Основная метрика выбора — профильная MAE медианной температуры в °C.
- Train-only scaler и ridge; persistence и rolling median для сравнения.
- Детекция на test; калибровка остатка на validation; фон из прошлых наблюдений.
- Статистические параметры детектора заданы как настройки, не как аварийные нормы.
- Длина в метрах по индексу ×0,0025, raw x сохранён без переинтерпретации.
- Исторические JOTB-документы отражают решения на момент их написания.

## Остались неизвестными

- Карта трассы и соответствие точек помещениям/оборудованию.
- Причина несоответствия разных численных шагов CSV заявленному разрешению.
- Когда полный профиль доступен относительно timestamp и задержка сбора.
- Истинные события, цена false positive/false negative, скрытая оценка организаторов.
- Подтверждённое разделение DTS/DAS; текущая реализация обрабатывает предоставленные
  числовые профили как температуру по ответу руководителя, не заявляет DAS-классификацию.
- Паспортные абсолютные температурные пределы и режимы HVAC.

Эти ограничения явно отражены в итогах и не блокируют воспроизводимое
температурное решение. Публикация и изменение внешних карточек не выполнялись.

## Переработка v2 по последнему уточнению пользователя

40 точек, 53 зоны, один 2.csv и прежние границы UTC не обязательны.
Актуальная задача и критерии всех этапов — task_revision.md.
Добавлены 24 признака, temporal/DSP ablation, постоянный train baseline,
поэлементные Δ-пороги только по train, происхождение ошибок/событий и отдельный
replay сохранённой модели. Регулярный интервал ограничен 0,5–1,5 train-cadence.
Минимальная шкала неопределённости: 0,2 °C для температурной разности,
0,4 °C для изменения экскурсии, включающей четыре измеренные величины.
Эти значения ограничивают статистический score, не задают аварийность.
