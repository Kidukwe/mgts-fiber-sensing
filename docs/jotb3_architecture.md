# JOTB-3: контракт причинных временных признаков

Область: только признаки доступной истории. Target, обучение, split и деплой
остаются вне реализации до решения команды. Минимальные модули:
`windowing.py` и `time_features.py`; без новых зависимостей и преобразований сетки.

## API окон — `windowing.py`

```python
@dataclass(frozen=True)
class ProfileWindow:
    profiles: tuple[Profile, ...]  # от старого к текущему
    session_index: int             # с нуля, локально для одного вызова

def iter_windows(
    profiles: Iterable[Profile],
    *,
    history_size: int,
    max_gap_seconds: float,
) -> Iterator[ProfileWindow]: ...
```

`history_size` — количество профилей, включая текущий; целое >= 2, bool
недопустим. `max_gap_seconds` — конечное положительное число, bool недопустим.
Каждый результат содержит ровно `history_size` профилей. На прогреве результатов
нет. После прогрева окно сдвигается на один профиль. Пустой вход даёт пустой выход.

Вход уже сгруппирован в непрерывные блоки одного файла/устройства/канала и
упорядочен внутри блока по времени. Функция не сортирует вход и не исправляет его.
Смена `(source_file, dts_id, channel_id, timezone_known)` начинает новую сессию.
Разные файлы разделяются консервативно: их принадлежность одной сессии неизвестна.
Смена координатной сетки (точное `np.array_equal`) или временной интервал
`> max_gap_seconds` тоже начинает сессию. Равенство порогу разрешено.
Несколько одновременных причин увеличивают номер сессии только один раз.

При неизменном ключе блока интервал <= 0 вызывает `ValueError`, в том числе при
смене сетки. Дубликаты не удаляются молча. Известные timezone сравниваются как
реальные моменты времени; naive-время остаётся отдельным локальным доменом.
Абсолютный timezone для него не назначается.

Немонотонные или пустые координаты, нечисловые/нефинитные массивы, несовпадающие
формы x/y/mask вызывают `ValueError`. Повторная валидация нужна для Profile,
созданных вручную, и потому что ingestion допускает NONINCREASING_X как warning.
Исходные массивы и профили не изменяются; окно удерживает максимум history_size
ссылок на профили. Номер первой сессии 0, последующих — 1, 2, ...

Отклонённые ingestion-записи нельзя просто скрыть и затем объявлять историю
непрерывной. API принимает Profile, поэтому вызывающий код должен разбить вход
на отдельные вызовы при отклонении записи. Автоматическая обработка
ProfileResult в этой версии не нужна. Пример использования обязан это объяснить.

## API признаков — `time_features.py`

```python
@dataclass(frozen=True)
class TimeFeatures:
    window: ProfileWindow
    x: NDArray[np.float64]
    lag_values: NDArray[np.float64]
    delta: NDArray[np.float64]
    rate: NDArray[np.float64]
    rolling_mean: NDArray[np.float64]
    rolling_std: NDArray[np.float64]
    valid_count: NDArray[np.int64]
    delta_seconds: float

def compute_time_features(window: ProfileWindow) -> TimeFeatures: ...
```

Данная функция также проверяет контракт окна: >= 2 профиля, один ключ блока,
одна строго возрастающая сетка и строго возрастающее время. Она не получает
max_gap_seconds; политика разрывов уже проверена iter_windows.

При N координатах и H профилях `lag_values.shape == (H, N)`. Строка 0 — текущий
профиль, строка 1 — предыдущий, и так далее. Значение -300 или True в
sentinel_mask превращается в NaN только в копии lag_values. Это политика
исключения подозрительного маркера из признаков, а не диагноз неисправности.

Остальные массивы имеют форму (N,):

- delta = lag_values[0] - lag_values[1]; NaN, если один из двух замаскирован.
- delta_seconds — реальный интервал между последними двумя профилями.
- rate = delta / delta_seconds; единицы y в секунду, не температура по умолчанию.
- rolling_mean — среднее незамаскированных значений текущего окна.
- rolling_std — стандартное отклонение с ddof=0; при одном значении равно 0.
- valid_count — сколько значений участвовало по каждой координате.
- при valid_count=0 mean/std равны NaN; предупреждений NumPy о пустом срезе нет.

`x` — копия сетки. Все выходные массивы read-only. window сохраняет время и
источник всех использованных профилей, позволяя проверить происхождение
признаков. Это не матрица для готового fit: NaN и зависимость координат ещё
потребуют решения в ML-эксперименте.

## Параллельная реализация и тесты

Агент реализации владеет только двумя модулями и документацией примера.
Агент тестов владеет `tests/test_time_features.py` и `tests/test_windowing.py`.
Согласованный API выше не меняется без сообщения координатору.

Численный пример: времена 0, 10, 30 секунд, одна координата, y = 1, 3, 9.
При H=3 lag_values = [[9], [3], [1]], delta=6, rate=0.3,
mean=13/3, std=sqrt(104/9), count=3. Подозрительные значения проверяются
отдельным примером, включая полностью замаскированную координату.

Обязательные тесты: численные формулы; прогрев; граница gap == порог и > порога;
смена файла/потока/сетки; дубликаты и обратное время; known-offset эквивалентность;
naive/aware граница; неизменность входов; read-only выход; полная/частичная маска;
невалидный конфиг и ручной Profile; причинность (изменение будущего не изменяет
уже выданные признаки); детерминизм повторного вызова. Target не конструируется.
