# JOTB-5: постановка ML-задачи и схема target

Статус: предложение на ревью команды. Документ задаёт задачу для первого воспроизводимого baseline. Он не утверждает, что модель распознаёт аварии.

## Краткое решение

Выбрать **регрессию**: по каждому фиксированному пространственному участку `2.csv` прогнозировать медиану записанного сигнала в следующем регулярном профиле, через 120–121 секунду после последнего профиля. Target вычисляется из реального следующего измерения, а не из оценки аномальности или придуманного класса. Аналитик может сравнить прогноз и поступившее измерение по участкам и выбрать большие расхождения для ручной проверки. Само расхождение не является подтверждённым событием.

## Основания и ограничения

- В `MGTS_data.zip/2.csv` есть поля `dts_id`, `channel_id`, `timestamp` и JSON-массив `points` из пар «координата, значение». Файл содержит 696 профилей одного сенсора и канала за 10.04.2026, 00:01:41–23:58:41 UTC. Среди интервалов 512 равны 120 секундам, 170 — 121 секунде, ещё 13 длиннее.
- Первые 2 121 координата образуют общую начальную часть всех профилей. Длина профиля составляет от 2 121 до 2 315 точек; 14 профилей короче 2 315.
- `reports/data_audit.md` описывает шесть исходных CSV, временные пропуски и отсутствие дубликатов ключа `(dts_id, channel_id, timestamp)`. В материалах нет таблицы размеченных событий или внешней измеряемой величины для target.
- Согласно `docs/decisions.md`, единицы координат и сигнала, соответствие файлов типам сенсоров и смысл `-300` в `5.csv` пока неизвестны. До уточнения нельзя называть значения `2.csv` температурой или вибрацией.
- Модули загрузки, окон, признаков и baseline в репозитории пока заготовки. Этот документ не означает, что они уже работают.

Числа и совпадение координат проверены разбором приложенного архива. `2.csv` выбран потому, что его время содержит смещение UTC, измерения покрывают почти сутки, а регулярные интервалы можно выделить без предположений о часовом поясе и значении `-300` в `5.csv`. Проверка на одном сенсоре, канале и дне не доказывает переносимость на другие объекты и даты.

## Чеклист и схема target

| Вопрос | Решение |
| --- | --- |
| Что предсказываем? | Числовую медиану сигнала участка в следующем профиле. Тип задачи — регрессия. |
| Кому это полезно? | Аналитик сравнивает прогноз и следующее наблюдение, чтобы выбрать участки для проверки. Оснований для автоматического объявления аварии пока нет. |
| Что является одним примером? | Пара «сенсор, канал, участок, момент решения `t`» и пять последовательных профилей, последний из которых получен в `t`. |
| Как задан участок? | Берём индексы точек `[0, 2120)` из `2.csv` и делим на 53 непересекающихся участка по 40 точек. Участок `z` содержит индексы `[40z, 40(z+1))`, где `z=0..52`. Оставшаяся общая точка исключается. Ширина 40 точек — выбор для baseline, а не подтверждённая физическая длина. |
| Откуда берётся target? | Для участка `z`: `y(z,t) = median(значений точек участка z в следующем профиле)`. Следующий профиль относится к тому же сенсору и каналу. При прогнозе в момент `t` он не входит в признаки. |
| Каков горизонт? | Одно следующее *регулярное* измерение. Все пять переходов между шестью профилями примера должны составлять 120–121 секунду. Окна с длинным пропуском исключаются: запоздалый профиль не считается двухминутным target. |
| Что доступно при прогнозе? | После получения полного профиля `t` доступны пять профилей до `t` включительно, их время, идентификатор сенсора и канала, индекс участка. Возможные признаки: медианы и разброс значений участка, последние изменения и краткосрочный тренд, рассчитанные только по этим профилям. Будущий профиль и статистики всего датасета недоступны. |
| Основная метрика? | Средняя абсолютная ошибка (MAE): сначала усредняем ошибки участков для каждого момента решения, затем — по моментам. Пока единицы неизвестны, сообщаем ошибку в единицах исходного сигнала. |
| Простой baseline? | «Последнее значение»: медиана участка в текущем профиле служит прогнозом следующей медианы. Дополнительно сравниваем с постоянной медианой участка, рассчитанной только на train. Обучаемую модель сравниваем прежде всего с последним значением. |

Target — сводка реального измеренного сигнала. Размеченных событий нет, поэтому точность классификации событий, precision/recall аномалий и качество обнаружения аварий оценить нельзя. Оценка аномальности или номер кластера не заменяют истинную разметку.

## Разделение на train, validation и test

Все границы относятся ко времени исходных профилей за 10.04.2026 в UTC. Все пять входных профилей **и** следующий профиль с target должны целиком находиться в одном блоке.

| Блок | Начало включительно | Конец не включительно | Допустимые окна из шести профилей в `2.csv` |
| --- | --- | --- | ---: |
| Train | 00:00 | 14:00 | 376 |
| Validation | 14:12 | 19:00 | 136 |
| Test | 19:12 | 24:00 | 112 |

Пропущенные 12 минут между блоками превышают примерно десять минут, охваченные четырьмя входными интервалами и горизонтом до target. Все пять переходов внутри допустимого окна должны составлять 120–121 секунду. Указано число **временных окон**. Умножение на 53 участка даёт зависимые примеры, а не столько же независимых испытаний. Реальное событие может длиться дольше 12 минут, поэтому следует проверить чувствительность результата к зазорам в 30 и 60 минут.

Разделение едино для всего канала: соседние участки и пересекающиеся окна не распределяются случайно между блоками. В эту оценку не добавляются другие файлы или каналы. Для заявления о переносимости потребуется отдельная проверка на целиком отложенном сенсоре, канале или дне после подтверждения сопоставимости сигнала и координат.

## Правила против утечки и схема оценки

1. Сначала определить блоки по времени, затем рассчитывать параметры предобработки и выбирать признаки. Масштабирование, заполнение пропусков, отбор признаков и преобразование target настраиваются только на train.
2. Для каждого примера проверить `max(feature_timestamp) <= t < target_timestamp`, принадлежность всех шести профилей одному блоку и отсутствие длинных интервалов.
3. Не использовать test при выборе признаков, ширины участка, параметров модели и решении о применении обучаемой модели. Для выбора служит validation.
4. Сравнить MAE на validation и затем на test с «последним значением» и постоянной train-медианой. Дополнительно показать RMSE, MAE по участкам и времени, относительное улучшение `1 - MAE_model / MAE_persistence`. Неопределённость оценивать по временным блокам, а не по отдельным соседним участкам и окнам.
5. Минимальный результат этапа baseline — воспроизводимое сравнение без утечек. Обучаемая модель полезна, если снижает MAE относительно последнего значения на validation и сохраняет преимущество на нетронутом test. Один день одного канала не даёт оснований заявлять производственную точность.

## Передача в JOTB-6

1. Реализовать чтение и проверку схемы `2.csv`, сохранить контрольную сумму файла и повторно проверить число строк, UTC-время, общую часть координат и интервалы.
2. Построить 53 ряда участков и допустимые окна из шести профилей. Проверить правила времени и разделения; сохранить таблицу признаков и target с указанием происхождения строк.
3. До обучения рассчитать прогноз «последнее значение» и постоянный прогноз, полученный только на train.
4. Вычислить признаки только из пяти прошлых профилей. Обучить одну простую регрессионную модель на train, выбрать её по MAE на validation и однократно оценить на test.
5. Сообщить метрики, число различных моментов решения, ошибки при быстрых изменениях сигнала и чувствительность к более широким зазорам. Если модель не превосходит «последнее значение», оставить его честным baseline.
