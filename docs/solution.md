# Контракт итогового решения

## Задача

Выдать инженеру ранжированные кандидаты изменений температуры вдоль волокна,
которые требуют проверки. Регрессионная цель формируется из следующего
измерения: метки аварий для обучения не нужны. Наличие скачка не равно протечке.

## Загрузка и DSP

`solution.extract`: исходные строки проходят существующий строгий parser.
Naive time получает подтверждённый UTC+3; исходная строка времени остаётся в
Profile. Предупреждения считаются по кодам. Rejected строки сохраняют границы
разрывов. Дубликат даёт пустые зоны и разрывает историю. Профиль не сортируется.

По последовательным участкам до 64 точек: медиана, исходные extrema и экскурсии,
std, абсолютный градиент, RMS высокочастотного остатка трёхточечного медианного
фильтра, доля FFT-энергии на пространственных частотах >=0,25 цикла/отсчёт.
Это **пространственный** спектр, не акустические герцы и не временная периодика.
Временная интерполяция не используется. Короткий крайний участок обрабатывается
по фактической длине; полностью маркерные зоны исключаются. Внутренние дырки
не склеиваются для FFT. Узкий пик сохраняется в исходных extrema.

Сетка каждого участка имеет fingerprint. Её смена, отсутствие участка, смена
потока/файла, неположительное время, rejected строка или интервал вне 0,5–1,5 train-cadence
разрывают соответствующую историю. Изменение хвоста не уничтожает пригодный префикс.

## Регрессия

`make_samples`: история пяти доступных прошлых профилей, target в следующем.
Признаки: два прошлых приращения трёх величин, отклонение последней величины от
медианы истории, пространственные признаки последнего профиля, P05/P95 и доли/серии поэлементных Δ,
sin/cos локального времени UTC+3. Всего 24 признака, три target.

Target — приращение медианы и двух экскурсий относительно последнего значения.
Прогноз абсолютной величины = последнее значение + прогноз приращения.
Прогноз экскурсий ограничивается снизу нулём; температура не обрезается.
`RidgeForecaster` решает регуляризованную задачу NumPy, без pickle.

Разбиение выполняется по индексу **целевого профиля** каждого файла: 60/20/20.
Train не содержит target из validation. Историю, уже доступную перед границей,
можно использовать в validation/test — это последовательный прогноз, не случайная
кросс-валидация. Модель и scaler после train не переобучаются.

Alpha 0.1/10/1000 и baseline выбираются по validation MAE медианной температуры.
Calibrating residual quantile на той же validation — инженерная калибровка,
не независимая conformal-гарантия. Test не используется для выбора параметров.
MAE/RMSE сначала усредняют зоны внутри timestamp, затем профили.
Нет независимой статистической оценки по количеству зависимых зон.

## Обнаружение

Для трёх величин объединяются два канала: остаток выбранного прогноза и
отклонение от медианы последних 30 принятых прошлых значений участка.
Порог первого — 99,5-й перцентиль абсолютного validation-остатка;
порог второго — 6 ×1,4826 MAD. Нижний предел — 0,2 °C для медианной температуры и 0,4 °C для изменения экскурсии.
Предел 0,2 °C относится к разности двух измерений
с заявленной абсолютной точностью ±0,1 °C. Точность не принимается за Gaussian σ.

Остаток модели учитывается только при совпадении знака с отклонением факта от
устойчивого фона и величине последнего за соответствующим пределом неопределённости. Это защищает от ложного обратного
события при восстановлении и экстраполяции модели за train-диапазон.
На test baseline замораживается при подозрении в любом из трёх каналов участка.
До test он адаптируется, не объявляя эти данные размеченной нормой.

Соседние подозрительные зоны объединяются в компоненту текущего профиля.
Компонента продолжается при пересечении с предыдущей в том же потоке, блоке и
совместимой сетке. Нужны два соседних профиля, start — первое подозрение,
detected_at — второе. При разветвлении используется жадное сопоставление;
это не точный трекер нескольких физических причин. Пропуск закрывает кандидата
без утверждения о восстановлении. `end_of_input` не означает устранение проблемы.
Каталог событий строится офлайн только на test. Этап прогноза использует прошлое;
онлайн latency не измерена.

Совместный рейтинг:
`ln(1+peak_ratio) * ln(2+duration/cadence) * sqrt(peak_extent/sample_spacing)`.
У рейтинга нет установленного порога аварийности; он сортирует очередь проверки.
Экстенты — покрывающие зоны, поэтому могут превышать реальный очаг.
Поле амплитуды отражает остаток победившего канала, а не абсолютную температуру.

## Артефакты и повторное использование

`model.json`: scaler, коэффициенты, intercept, alpha, feature_names, target_names,
champion, пороги, семантика, source SHA, split, параметры окон и gaps.
`RidgeForecaster.from_dict(artifact['ridge'])` восстанавливает обученную модель.
`forecast.predict_artifact` применяет champion к готовым причинным признакам,
последнему значению и медиане истории. Нельзя подавать raw CSV напрямую в матрицу признаков.

`predictions.npz` содержит доступные для проверки test-входы, факты, прогнозы,
origin/target timestamps, source row и индексный участок. Для JSON запрещены NaN.
В `solution.json` — входные SHA и SHA модулей, versions и метрики всех baseline.
Проверка совпадения SHA обязательна, raw никогда не записываются.

## Проверка и интерпретация

Тесты проверяют причинность, границы target, сбросы истории, маркеры, timezone,
сохранность raw, переносимость модели, устойчивый сдвиг и восстановление.
Контролируемая синтетика содержит четыре простые формы, использованные при
разработке. Её precision/recall — функциональная проверка этих сценариев, не
независимая оценка и не качество на реальных авариях. Отдельной реальной разметки нет.

Тип здания влияет на форму нормального фона, расписание, теплопередачу,
пороговые температуры оборудования и трактовку знака. Горячая и холодная протечки
могут давать противоположные признаки. Без схемы укладки и внешних наблюдений
алгоритм не может надёжно установить причину или конкретную коммуникацию.

## Дополнения v2

Требования после ответа руководителя имеют приоритет над геометрией ранних PR.
Ширина зоны настраивается CLI; фиксированный default не является ограничением кейса.
Доли положительных/отрицательных Δ и максимальные соседние серии вычисляются по
совпадающим raw x. Порог участка — P95 |Δ| только train, минимум 0,2 °C.
Нет пары / нерегулярное время — нулевая pair_fraction, а не выдуманное наблюдение.

Сравниваются temporal-only и spatial/DSP ridge с одинаковыми target/окнами,
alpha выбирается отдельно по validation. Дополнительный baseline — постоянная
train-медиана каждой зоны. Все baseline имеют сохранённые test-метрики.
Ошибки по зонам, трём target и быстрым изменениям находятся в metrics.json;
граница быстрого изменения оценивается только по train.

Событие содержит peak_evidence: исходные row/line, timestamp, наблюдаемую
температуру, референс величины победившего канала, фактическую скорость изменения
за реальное Δt, доли и длины изменившихся последовательностей. quality_flags
сохраняются. Для всех ingestion-проблем экспортируется issues.jsonl.

`scripts/predict_solution.py` применяет сохранённый champion, scaler и пороги
к новым CSV того же сенсора/канала. Fit не вызывается; это batch replay,
не непрерывный online-сервис. Повтор исторического файла не считается новым test.
Восстановление champion использует feature_indices; у train_median передаются zone_ids.

Набор записей уже использовался при разработке v1. Повторная оценка v2 не является
новой независимой оценкой; для подтверждения переносимости нужен новый период/объект.


Проверка поставки без исходных CSV: `python scripts/verify_solution.py --skip-raw`.
Сборка архива сначала проверяет актуальность кода и воспроизведение test-прогнозов;
при изменившемся коде требуется пересоздать результаты.

Детектор получает начальный фон из тех же пяти прошлых профилей, которые уже
доступны прогнозу. Дополнительного слепого прогрева по новым target не требуется.
При расширении события проверяется любая общая зона с совместимой сеткой,
поэтому расширение влево не меняет исходные start/detected_at.
