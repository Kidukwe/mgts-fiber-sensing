# JOTB-2: read-only ingestion

Загрузчик принимает CSV с `dts_id`, `channel_id`, `timestamp`, `points`.
Одна запись — один профиль одного канала в момент времени. `points` — JSON-список
пар чисел `[x, y]`; `points_size` необязателен. Единицы и физический смысл осей
загрузчик не предполагает. Дополнительные CSV-колонки допускаются, но не входят в Profile.

## Запуск

Из корня репозитория:

```bash
source .venv/bin/activate
python -m pip install -e '.[dev,notebooks]'
python scripts/validate_data.py --data-dir MGTS_data --report-dir reports/ingestion
pytest
ruff check .
```

CLI сохраняет сводку, конфигурацию проверки, версии Python/NumPy и SHA256 каждого
CSV в `summary.json`; все проблемы, включая предупреждения, — в `issues.jsonl`.
Exit code 0 означает отсутствие отклонений и файловых ошибок, а НЕ отсутствие предупреждений.
Exit code 1 означает ошибки или изменение SHA256; 2 — некорректные аргументы.
Каталог отчётов нельзя разместить внутри каталога исходных данных. Существующие
производные отчёты при повторном запуске обновляются; CSV никогда не записываются.

## Минимальный пример API

```python
from pathlib import Path
from mgts_sensing.io import iter_profiles

loaded = rejected = 0
for result in iter_profiles(sorted(Path("MGTS_data").glob("*.csv"))):
    for issue in result.issues:
        print(issue.source_file, issue.line_number, issue.severity,
              issue.code, issue.description)
    if result.row_number == 0:  # отдельное событие уровня файла/заголовка
        continue
    if not result.loaded:
        rejected += 1
        continue
    loaded += 1
    profile = result.profile
    # x/y имеют свою длину и сетку, не объединяйте их через np.stack без проверки.
    # profile.sentinel_mask показывает y == -300; значения не удалены/не заменены.
    # Здесь можно передавать профиль в визуализацию или согласованный DSP.
print(loaded, rejected)
```

Итератор выдаёт `ProfileResult`, а не только хорошие профили: ошибки нельзя потерять
из-за внутреннего `continue`. Сам потребитель обязан обработать `issues` и отклонения.

## Структура Profile

| Поля | Содержание |
| --- | --- |
| `source_file`, `row_number`, `line_number` | Path источника, индекс записи данных с 1, физическая строка начала с 1; заголовок — строка 1 |
| `dts_id`, `channel_id` | Строковые идентификаторы, без переименования/приведения к числу |
| `timestamp`, `timestamp_raw` | datetime и точный исходный текст |
| `timezone_raw`, `utc_offset_seconds`, `timezone_known` | Исходное обозначение смещения, смещение в секундах и наличие известного timezone |
| `timestamp_format_normalized` | Был ли текст приведён к формату, понятному Python 3.10: `+03` → `+03:00`, `Z` → `+00:00`, пробелы по краям |
| `x`, `y` | Одномерные массивы float64 одинаковой длины; исходный порядок сохранён |
| `sentinel_mask` | Булева маска `y == -300`, не метка отказа |
| `points_size` | Заявленная длина либо None, если поля нет/значение невалидно |
| `quality_flags` | Коды предупреждений этой записи |

Массивы read-only: обработка должна явно создавать производную копию.
Преобразование чисел в float64 не является нормализацией; очень большие целые
могут терять точность представления, значения вне диапазона float64 отклоняются.

## Политика проверок

Errors отклоняют профиль целиком. Даже одна испорченная пара не удаляется незаметно.
Warnings сохраняют профиль и исходные значения: пригодность для дальнейшего DSP
или ML требует отдельного решения, `loaded=True` не означает пригодность для модели.

| Severity | Коды и причины |
| --- | --- |
| error | `MISSING_REQUIRED_FIELD`, `INVALID_TIMESTAMP`, `INVALID_JSON`, `INVALID_POINTS_STRUCTURE`, `EMPTY_PROFILE` |
| error | `INVALID_POINT_PAIR`: не список из двух элементов; `NONNUMERIC_POINT`: строки, bool, null; `NONFINITE_POINT`: NaN/Inf/переполнение |
| error | `MISSING_COLUMN`, `DUPLICATE_COLUMN`, `CSV_COLUMN_COUNT`, `FILE_READ_ERROR`, `EMPTY_FILE`, `CSV_READ_ERROR` |
| warning | `INVALID_POINTS_SIZE`, `POINTS_SIZE_MISMATCH`: заявленная длина не мешает разобрать исходные пары |
| warning | `NONINCREASING_X`: повторяющиеся/убывающие координаты, без сортировки и удаления |
| warning | `UNKNOWN_TIMEZONE`: время остаётся naive; `SUSPECT_SENTINEL`: подозрительное значение -300, без физической трактовки |
| warning | `DUPLICATE_KEY`: повтор ключа во всём вызове итератора; строки не удаляются |
| warning | `PROFILE_LENGTH_CHANGED`, `GRID_CHANGED`: изменение относительно предыдущего загруженного профиля того же потока |

`Issue` содержит файл, индекс записи, физическую строку, severity, code и description.
Ошибки заголовка/открытия файла имеют `row_number=0`. При неправильной схеме
каждая читаемая запись дополнительно получает своё отклонение.

Дубликаты определяются по `(dts_id, channel_id, timestamp)`: timezone-aware время
сравнивается как UTC instant; разные записи `+03` и `Z` того же момента совпадают.
Naive время сравнивается только с naive, не с UTC. `5.csv` не получает timezone.
Имя файла НЕ часть ключа: одинаковый dts_id в разных файлах ожидаем, но сам по себе
не является дубликатом. Ключ учитывается и у отклонённой записи, если её метаданные
разбираются: предупреждение ссылается на первое появление файла/строки.

Сетка сравнивается точно по float64 (SHA256), без допуска близости. Поток диагностики
сетки — dts_id + channel_id + известность timezone, включая границы файлов.
Порядок файлов задаёт вызывающий код; предупреждения о переходах зависят от этого
порядка, а не от сортировки по времени. Это НЕ определение физической сессии.

## Ограничения и воспроизводимость

- Загрузчик держит в памяти текущую запись и ключи дубликатов: O(размер профиля +
  число ключей). Сами профили потоковые; CLI дополнительно хранит timestamps для
  расчёта интервалов, но не все x/y. Повторный вызов сбрасывает состояние.
- При сломанном CSV quoting/кодировке границы оставшихся записей могут быть
  неустановимы. Итератор сообщает `CSV_READ_ERROR` и переходит к следующему файлу;
  отчёт имеет `accounting_complete=false`. Это нельзя выдавать за полный учёт
  повреждённого файла. Для текущих шести CSV учёт полный.
- Нет автоисправления, интерполяции, обрезки, фильтрации, удаления дубликатов,
  общей сетки, нормализации, FFT/STFT или обучения. Физические диапазоны и
  статистические выбросы не объявляются ошибками без подтверждения единиц.
- Notebook использует общий parser для аудита; его таблицы/графики рассчитаны на
  текущие шесть CSV, CLI предпочтителен для отчёта произвольных повреждённых файлов.
  Старые пользовательские outputs notebook не перезаписывались; выполните Run All.
- Загрузка детерминирована при одинаковых файлах и порядке. Seed не требуется;
  случайная выборка визуализации notebook по-прежнему имеет seed=42.
- SHA256 фиксирует версию локального набора, но не заменяет описание происхождения
  данных организаторами. Проверка до/после не защищает от параллельной записи между
  этими моментами; исходники следует держать неизменяемыми.

## Проверка гипотез без leakage

Сначала сравнивайте профили по источнику/каналу, локальной сетке и известности
timezone; проверяйте изменения сетки и долю `sentinel_mask`. Не вычитайте соседние
профили с разными x и не совмещайте `5.csv` с UTC без подтверждения смещения.
Для гипотез можно строить диагностические графики, явно показывая/маскируя -300
как технического кандидата, но нельзя считать маску целевой меткой.

Перед будущим ML отдельно согласовать split, единицы/модальность, цель и метрику.
Дубликаты и близкие по времени профили одного канала могут попасть в train/test;
одинаковый dts_id может связывать разные файлы. Не считайте файл независимым
устройством. Любые обучаемые преобразования должны fit только на train.

Три обязательных фрагмента кода для понимания: `parse_profile` (целостность записи
и error/warning), `iter_profiles`/`record_key` (учёт строк и timezone-aware
дубликаты), обработка `result.loaded`/`issues`/`sentinel_mask` в примере выше.
